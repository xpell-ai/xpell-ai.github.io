How It Works

Visual Xpell turns developer intent into reviewed runtime operations before changes are applied.

  1. DescribeTell Visual Xpell what you want to build or change.
  2. ReviewReview the application plan and intended runtime operations.
  3. ApplyCreate or update views, entities, flows, and application objects.
  4. Continue LiveUse the application immediately and keep evolving it while it runs.

Not just generated code. A live application runtime.

Traditional AI coding workflows generate files and wait for the next build cycle. Visual Xpell works with the structure of the running application, allowing supported changes to be planned, validated, and applied through the Xpell Runtime.

Xpell Runtime is the technology beneath Visual Xpell. It keeps application structure explicit, inspectable, and available to normal engineering workflows.

@xpell/core

XData 2, Nano-Commands 2, XEM, XModule, and XObject.

@xpell/node

xnode server execution, Wormholes 2 transport, and XDB persistence.

@xpell/ui

XUI, XUIObject, browser runtime views, and client Wormholes.

@xpell/3d

A three.js-based spatial layer for interactive 3D application surfaces.

Why runtime matters: AI can collaborate with a running system instead of only generating source files for a later build cycle.

Why Xpell Exists

WordPress made websites editable. Xpell explores making applications editable.

The original goal was reducing the cost and delay of software changes: fewer delivery cycles for simple interface, CRUD, flow, and application structure updates.

AI later transformed this runtime direction into an AI-native application platform, with Visual Xpell as the product experience built on top.
